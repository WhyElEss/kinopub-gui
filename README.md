# kino.pub downloader · GUI

**Программа для скачивания с [kino.pub](https://kino.pub) с нормальным интерфейсом.** Запускаете — открывается вкладка в браузере. Ищете по каталогу, смотрите превью прямо в плеере и качаете: фильмы и сериалы целиком, со всеми озвучками и субтитрами. Пока идёт загрузка, видно прогресс по каждому эпизоду — скорость и сколько осталось.

Войти нужно один раз, по короткому коду устройства. Внутри ничего лишнего: один файл, без Electron и без Node (Go-сервер со встроенным интерфейсом на React). Запустили — и пользуетесь.

> **Это форк [ZioSHik/kinopub-gui](https://github.com/ZioSHik/kinopub-gui)**, доработанный для запуска на домашнем сервере. Отличия от апстрима: [шаблоны папки и имени файла](#6-папка-и-имя-файла) вместо жёсткой раскладки `Название/Season NN/SNNENN`, флаг [`-lan`](#флаги) для доступа по локальному IP, флаг `-no-self-update` и [сборка в Docker](#запуск-на-домашнем-сервере-docker).

## Возможности

- 🎬 **Просмотр каталога** — поиск, топы, подборки, фильтры по жанру и стране, диапазоны по году и рейтингу IMDb/Кинопоиск, ваша история просмотров и «продолжить просмотр», а также страница тайтла с описанием, актёрами, рейтингами и полным деревом сезонов и эпизодов.
- ▶️ **Встроенный плеер** — посмотрите превью любого тайтла прямо в приложении, прежде чем качать. Поток идёт через само приложение, так что в браузере ничего настраивать не нужно.
- 🎬 **Загрузка без потерь** — все аудиодорожки, все субтитры, целые многосезонные сериалы — выбранные из каталога или вставленные прямой ссылкой.
- ⚡ **Живой прогресс** — проценты по каждому эпизоду и каждой аудиодорожке, скорость и оставшееся время — всё обновляется в реальном времени.
- 🔊 **Выбор озвучек** — отметьте, какие дорожки оставить, прямо на странице тайтла (выбор запоминается) или в таймерном окне при загрузке по ссылке; выбор обобщается по всем эпизодам.
- 🩺 **Доктор** — проверяет загрузки по файлу состояния и исправляет несоответствия, с понятным отчётом.
- 📚 **Библиотека** — просматривайте уже скачанное с размерами, разрешениями и обнаружением пропавших файлов; откройте готовый файл или покажите его папку.
- 🔐 **Вход один раз** — авторизация по короткому коду устройства; токены хранятся в зашифрованном виде и привязаны к машине. Локальные функции (Библиотека, Доктор, Настройки) работают и без входа.
- 🌍 **Два языка** — английский и русский, переключаются в один клик (запоминается между сессиями).
- 📦 **Один бинарник** — интерфейс встроен внутрь, никакого Electron и Node во время работы; либо запуск в Docker на домашнем сервере.

## Требования

- **ffmpeg** — им приложение склеивает видео, звук и субтитры в один файл. Если он стоит в системе (есть в `PATH`), приложение подхватит его само; на странице «Настройки» видно зелёную или красную отметку для `ffmpeg` и `ffprobe`.
  ```bash
  brew install ffmpeg          # macOS
  sudo apt install ffmpeg      # Debian/Ubuntu
  ```
  ```powershell
  winget install Gyan.FFmpeg   # Windows (или: choco install ffmpeg / scoop install ffmpeg)
  ```
  На Windows убедитесь, что `ffmpeg.exe` и `ffprobe.exe` есть в `PATH` (менеджеры пакетов выше делают это сами) — страница «Настройки» подтвердит, что оба найдены.

  **Не хотите ставить руками?** Если ffmpeg не найден, нажмите **Настройки → Система → Установить ffmpeg** (такая же кнопка есть на странице «Загрузка») — приложение само скачает готовую сборку под вашу систему и дальше будет пользоваться ей. В систему ничего не прописывается, права администратора не нужны.
- Браузер (приложение открывается в том, что стоит по умолчанию).
- Аккаунт kino.pub с активной подпиской — без неё не будет ни каталога, ни просмотра, ни загрузок.

## Установка и запуск

Готовых бинарников нет: ни в этом форке, ни в апстриме на GitHub релизы не опубликованы (`ZioSHik/kinopub-gui/releases` пуст). Собирайте одним из двух способов.

### Вариант A — Docker (домашний сервер, NAS, Raspberry Pi)

Основной способ в этом форке — см. [Запуск на домашнем сервере](#запуск-на-домашнем-сервере-docker). Ничего, кроме Docker, ставить не нужно: ffmpeg и интерфейс уже внутри образа.

### Вариант B — сборка из исходников

Понадобятся Go 1.26+ и Node 20+ (только для сборки интерфейса; во время работы не нужны).

```bash
git clone https://github.com/WhyElEss/kinopub-gui
cd kinopub-gui
make run          # собирает веб-интерфейс, бинарник GUI и запускает его
```

Или по шагам:

```bash
make web          # собрать React-фронтенд в web/dist (встраивается через go:embed)
make gui          # собрать бинарник ./kinopub-gui
./kinopub-gui     # → откроет http://127.0.0.1:8765 в браузере
```

Бинарник самодостаточный: React-интерфейс встроен внутрь через `go:embed`, а собранный `web/dist` закоммичен — поэтому `go build ./cmd/kinopub-gui` работает и без Node (`make web` пересобирает интерфейс, если вы правили фронтенд). Кросс-сборку под все платформы делает `make release-gui`, а `make dmg` собирает macOS-приложение.

> `go install github.com/ZioSHik/kinopub-gui/cmd/kinopub-gui@latest` ставит **апстрим**, без правок этого форка: путь модуля в `go.mod` остался апстримовым, чтобы не переписывать все импорты. Для форка — `make` или Docker.

Приложение не подписано сертификатом Apple и Microsoft, поэтому свою же сборку macOS и Windows при первом запуске покажут предупреждение (**Конфиденциальность и безопасность → Все равно открыть** / **Подробнее → Выполнить в любом случае**). Учётные данные хранятся в зашифрованном виде в `~/.config/kinopub/credentials.enc` (`%USERPROFILE%\.config\kinopub\credentials.enc` на Windows).

### Флаги

```
kinopub-gui [flags]
  -addr            address to listen on (default 127.0.0.1:8765;
                   falls back to an ephemeral port if taken)
  -no-open         do not open the browser automatically
  -lan             accept requests from the local network too
  -no-self-update  disable the in-app updater (container/package installs)
  -version         print version and exit
```

По умолчанию сервер слушает только на вашем компьютере (`127.0.0.1`) — это не публичный сервис, снаружи к нему не подключиться. Вдобавок он отклоняет чужие запросы, чтобы посторонняя страница в браузере не могла им потихоньку воспользоваться.

`-lan` снимает это ограничение для локальной сети: вместе с `-addr 0.0.0.0:8765` приложение становится доступно по адресу вроде `http://192.168.2.200:8765` с любого устройства в доме. Принимаются только приватные адреса (RFC1918, link-local), имена `*.local` и однословные хосты; публичные домены по-прежнему отклоняются. **Входа в приложении нет** — любой, кто дотянется до порта, получает доступ к файловой системе сервера, к загрузкам и к вашему аккаунту kino.pub. Не пробрасывайте этот порт наружу.

### Обновление

Обновление форка — это `git pull` и пересборка (`make run`, а в Docker `docker compose up -d --build`).

Встроенный автообновлятор из апстрима остался в коде, но полагаться на него здесь не на что: он ищет релизы в `ZioSHik/kinopub-gui`, а их там нет, — **Настройки → Обновление ПО** просто покажет текущую версию. В контейнере он выключен флагом `-no-self-update` и сообщает об этом прямо в интерфейсе.

## Как пользоваться

### 1. Вход

Локальные функции — **Библиотека, Доктор, Настройки, выбор папки** — работают без входа. Каталог, поиск, встроенный плеер и загрузки требуют аккаунт.

Нажмите **Войти** (вверху справа или в боковой панели) и:

1. Приложение покажет короткий **код устройства** и ссылку (`kino.pub/device`).
2. Откройте эту ссылку в любом браузере, где вы залогинены в kino.pub, и введите код.
3. Подтвердите — приложение распознает это за пару секунд, и вы внутри.

Устройство появится в списке устройств вашего аккаунта kino.pub как `kinopub-gui (имя-компьютера)`. Токены хранятся зашифрованными, привязаны к вашему компьютеру и лежат в `~/.config/kinopub/credentials.enc`. Выйти можно в любой момент из «Настроек».

> **kino.pub часто недоступен без VPN.** Если вход, каталог или загрузки зависают или отваливаются по таймауту, включите VPN или укажите прокси (Настройки → Прокси либо для конкретной загрузки в «Дополнительно»). Интерфейс показывает напоминание и определяет таймауты.

### 2. Найти что-нибудь

Откройте **Каталог**, чтобы искать и просматривать. Фильтруйте по типу, жанру, стране, диапазону лет и рейтингу IMDb/Кинопоиск; смотрите топы и подборки; или возвращайтесь к строкам **истории** и **продолжить просмотр**. Откройте тайтл, чтобы увидеть детали, рейтинги, доступные озвучки и полное дерево сезонов и эпизодов — и нажмите ▶, чтобы **посмотреть превью во встроенном плеере** перед загрузкой.

Также можно вставить ссылку kino.pub прямо на странице **Загрузка**, если она у вас уже есть.

### 3. Загрузка

Из страницы тайтла (или со страницы «Загрузка») отметьте нужные сезоны и эпизоды, выберите качество и нажмите **Начать загрузку**. Прогресс появляется в **Очереди** — общий, по каждому эпизоду и по каждой дорожке, со скоростью и оставшимся временем.

Под кнопкой **Дополнительно** — тонкая настройка: контейнер (MKV / MP4), параллелизм, число повторов, ограничение скорости запросов, прокси (HTTP/HTTPS/SOCKS5), тогглы «Перекачать заново» и «Без чанков» (стримить всё через ffmpeg), подробные логи и поле для своих аргументов ffmpeg. Поля подставляются из «Настроек», так что обычно тут ничего трогать не нужно.

### 4. Аудиодорожки

Озвучки выбираются прямо там, где вы начинаете загрузку:

- **Со страницы тайтла** в каталоге — в блоке «Озвучка» отметьте галочками дорожки, которые хотите оставить («Выбрать все» / «Снять все»). Выбор запоминается и подставляется на следующих тайтлах; если вашей прошлой озвучки тут нет, приложение подскажет выбрать другую.
- **При загрузке по прямой ссылке** (страница «Загрузка») выбор всплывает таймерным окном уже при старте: отметьте нужные дорожки, «Только эта» — оставить одну, «Оставить все» — взять всё (то же срабатывает по истечении таймера).

Выбор обобщается по всем эпизодам и сопоставляется по языку: если выбранной озвучки в каком-то эпизоде нет, движок берёт другую дорожку на том же языке. По умолчанию сохраняются все дорожки.

### 5. Доктор и Библиотека

- **Доктор** проверяет файлы по файлу состояния (отсутствует, обрезан, несовпадение размера, неполная запись, осиротевший `.tmp`) и чинит их в один клик — тоггл «Починить» (убрать битые записи и файлы) и «Удалить .tmp». Сверяет наличие файла и записанный размер на диске — быстрый офлайн-проход без обращения к сети.
- **Библиотека** сканирует обе папки вывода (и дополнительные из Настроек) на файлы `.kinopub-state.json` и показывает всё скачанное, отмечая файлы, пропавшие с диска. Откройте или покажите любой файл прямо из списка.

### 6. Папка и имя файла

Куда лягут файлы, задаётся тремя вещами: папкой вывода (выбирается кнопкой) и двумя шаблонами — **Папка** и **Имя файла**. Полный путь получается как `<папка вывода>/<шаблон папки>/<шаблон имени>.<mkv|mp4>`; в шаблоне имени можно использовать `/`, чтобы добавить вложенность (так по умолчанию делается папка сезона). Под полями сразу показывается, что получится.

Подстановки:

| Токен | Значение |
| --- | --- |
| `{title}` | название как отдаёт kino.pub, например `Рик и Морти / Rick and Morty` |
| `{ru}` | русская половина названия |
| `{original}` | оригинальная половина (или `subname` из API) |
| `{year}` | год выпуска |
| `{season}`, `{episode}` | номера; `{season:02}` — с ведущим нулём |
| `{epTitle}` | название серии |
| `{quality}` | качество, например `1080p` |
| `{id}` | id тайтла на kino.pub |

Слэш **внутри** значения (в названии) папку не создаёт — он заменяется на `_`; каталоги появляются только там, где вы поставили `/` в самом шаблоне. Пустые компоненты выбрасываются, а если шаблон схлопнулся в пустоту, берётся запасное имя (`series_<id>` / `S01E01`).

Настройки хранят **отдельный набор для сериалов и для фильмов** — свою папку вывода и свою пару шаблонов. Приложение само подставляет нужный набор, когда вы открываете тайтл: сериал уедет, например, в `/media/TV`, фильм — в `/media/Movies`. Если папка для фильмов не задана, они кладутся туда же, куда сериалы. В окне тайтла (блок **Куда сохранить**) и папку, и шаблоны можно поменять для конкретной загрузки. Заводские шаблоны:

```
сериалы:  {title}                +  Season {season:02}/S{season:02}E{episode:02}
фильмы:   {original} ({year})   +  {original} ({year})
```

Раскладка для фильмов отличается от апстрима намеренно: `The Matrix (1999)/The Matrix (1999).mkv` — то, что ожидают Plex, Jellyfin и Emby (по оригинальному названию они и сопоставляют метаданные), тогда как фильм внутри `Season 01/S01E01.mkv` они опознают плохо. Если у фильма нет отдельного оригинального названия, `{original}` подставит русское.

**Пустое поле — это не «без папки»:** и сервер, и предпросмотр подставляют туда встроенное значение по умолчанию. Шаблон папки всегда даёт минимум один каталог — см. врезку ниже.

> Файл состояния `.kinopub-state.json` и постер лежат в папке серии (шаблон **Папка**), поэтому этот шаблон всегда должен давать хотя бы один каталог — иначе два тайтла в одной папке перезаписали бы состояние друг друга. Если поменять шаблон у уже скачанного тайтла, приложение будет считать его новым: старые файлы останутся на месте, но «уже скачано» к ним больше не привяжется.

### 7. Качество

В выпадающем списке качества два пункта — не разрешения:

- **Авто (оптимально)** (пустое значение) — компромисс по битрейту: 1080p h264 до ~3000 кбит/с, иначе лучший 720p. Именно оно стоит по умолчанию, и до 2160p оно не доходит никогда.
- **Максимальное** — вариант с наибольшим битрейтом из доступных; только он берёт 4K, когда файл есть.

Остальные пункты — конкретные разрешения (`1080p`, `720p`, …), и список подставляется из того, что реально есть у тайтла. Значение по умолчанию — в Настройках, для конкретной загрузки — в окне тайтла.

### 8. Настройки

Значения по умолчанию для новых загрузок (папки вывода и шаблоны путей — отдельно для сериалов и фильмов, качество, контейнер, параллелизм, повторы, ограничение скорости, прокси), а также дополнительные папки для сканирования в Библиотеке, вход в kino.pub, установщик ffmpeg и обновление ПО. Хранятся в `~/.config/kinopub/gui.json` (или в `$XDG_CONFIG_HOME/kinopub/gui.json`).

## Запуск на домашнем сервере (Docker)

Для NAS/Raspberry Pi в репозитории есть `Dockerfile` (UI + статический бинарник + ffmpeg) и `deploy/docker-compose.yml`. Собирается под ту же архитектуру, на которой запускается — на Pi это нативный arm64, без эмуляции.

```bash
git clone https://github.com/WhyElEss/kinopub-gui ~/kinopub-gui
cd ~/kinopub-gui/deploy
# поправьте volumes (папка медиатеки) и TZ под себя
docker compose up -d --build
```

Дальше откройте `http://<ip-сервера>:8765` с любого устройства в сети и войдите в kino.pub по коду.

Что важно знать про такой запуск:

- контейнер стартует с `-addr 0.0.0.0:8765 -lan -no-open -no-self-update`; **аутентификации нет**, так что держите порт внутри локальной сети;
- выбор папки в интерфейсе показывает файловую систему **контейнера** — доступно ровно то, что вы примонтировали (в примере `/mnt/share/Media` → `/media`);
- `user: "1000:1000"` — файлы пишутся от имени хозяина медиатеки, а не от root;
- `/config` (настройки и зашифрованные токены kino.pub) лежит в именованном томе `kinopub-config`, а не в папке репозитория — иначе `git clone`/rsync поверх исходников стёр бы сохранённый вход. Посмотреть содержимое: `docker run --rm -v kinopub-config:/c alpine cat /c/kinopub/gui.json`;
- `KINOPUB_OUTPUT_DIR` задаёт папку загрузки при первом запуске (дальше значение берётся из настроек);
- `/etc/machine-id` монтируется с хоста: ключ шифрования токенов выводится из него, а без файла он подменяется идентификатором загрузки, который меняется при каждой перезагрузке — и вход приходилось бы повторять;
- встроенный автообновлятор выключен: образ обновляется пересборкой (`docker compose up -d --build`).

## Как это устроено

```
┌──────────────────────────────┐        SSE (live progress)        ┌───────────────────────┐
│  React + TS + Tailwind UI     │ ◀───────────────────────────────── │  Go HTTP server       │
│  (embedded via go:embed)      │ ──── REST (commands) ────────────▶ │  internal/gui         │
└──────────────────────────────┘                                    └─────┬───────────┬─────┘
                                                                          │ drives    │ API
                                                          ┌───────────────▼──┐   ┌────▼──────────────┐
                                                          │ kinopub engine    │   │ kino.pub API      │
                                                          │ internal/app +    │   │ services/kinopubapi│
                                                          │ services (HLS,    │   │ (device login,    │
                                                          │ downloader, …)    │   │ discovery, stream)│
                                                          └───────────────────┘   └───────────────────┘
```

Сервер не запускает движок отдельным процессом, а работает с ним напрямую в одной программе: прогресс загрузки уходит в браузер живым потоком, выбор озвучки всплывает окном и держит загрузку до вашего ответа, а лог движка виден в логе каждой задачи.

Каталог и просмотр работают через `internal/services/kinopubapi` — небольшой клиент к API kino.pub: он держит вход и сам обновляет токены. Плеер получает видео через `/api/hls` — это прокси внутри самого приложения; каждая ссылка подписана, так что использовать его как чужой открытый прокси не выйдет.

### Структура проекта

```
cmd/
  kinopub-gui/      входная точка GUI-сервера (встраивает UI, открывает браузер, трей для macOS/Windows)
internal/
  app/kinopub/      корень композиции движка (App.Run)
  domain/           порты и модели
  services/
    kinopubapi/     клиент API kino.pub (вход устройства, обнаружение, разрешение потока)
    downloader/     загрузка HLS + файлов, сборка через ffmpeg
    hlsdownloader/  разбор HLS-манифестов и загрузка сегментов
    doctor/         проверка и починка загрузок
    statestore/     .kinopub-state.json по каждому сериалу
    …               outputlayout, scheduler, progress, proxyprovider
  gui/              REST + SSE сервер, менеджер задач, обнаружение, HLS-прокси плеера, reporter/chooser
  lib/              credstore (шифр. учётки), httpx (uTLS), logx, audiomenu, …
web/                фронтенд React + Vite + Tailwind
  dist/             собранный UI, встроенный в бинарник (go:embed)
Dockerfile          сборка образа: UI → статический бинарник → Alpine с ffmpeg
deploy/             docker-compose.yml для домашнего сервера
```

## Разработка

```bash
# Терминал 1 — запустить Go-сервер (раздаёт встроенный UI + API)
make gui && ./kinopub-gui

# Терминал 2 — фронтенд с горячей перезагрузкой и прокси API на :8765
make dev            # → http://localhost:5173
```

`make vet` запускает `go vet`, `make test` — набор тестов. CI собирает интерфейс, прогоняет vet и тесты (включая детектор гонок) на Linux, Windows и macOS.
